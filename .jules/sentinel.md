
## 2024-05-27 - Command Injection & Secret Leakage in GitHub Clone Endpoint
**Vulnerability:** The `/api/github-clone` endpoint used `exec` with a raw interpolated command string for `git clone`, susceptible to command injection via `repoName` and argument injection via `authUrl`. Additionally, the endpoint interpolated `githubToken` directly into `authUrl` without sanitizing it in the `catch` block's error message, causing the token to leak to the client if the `git clone` execution failed.
**Learning:** Raw command interpolation with `exec` can allow both command and argument injection. Embedding credentials in URLs passed to shell commands increases the risk of those credentials being leaked in error logs or client responses when the execution fails and returns the raw command string in the error message.
**Prevention:** Always use `execFile` with an array of arguments and the `--` separator to explicitly delineate command options from user input. Validate user inputs (e.g., using regex `/^[a-zA-Z0-9_.-]+$/`) to ensure they are safe directory/file names. Always sanitize error messages using regex to mask embedded credentials (e.g., `.replace(/https:\/\/[^@]+@/g, 'https://***@')`) before returning them in API responses.
