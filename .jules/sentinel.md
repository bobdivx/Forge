## 2024-11-20 - [Command Injection in docker-logs.ts]
**Vulnerability:** Command injection and error detail leakage in `src/pages/api/docker-logs.ts`. User input `containerId` and `tail` were directly interpolated into a shell string executed via `execSync` without sanitization or validation, allowing arbitrary shell command execution. Additionally, exceptions were bubbling up `error.message` to the client response, which could expose internal system details or sensitive secrets.
**Learning:** Shell interpolation (`execSync(commandString)`) is highly dangerous when any part of the string is derived from user input. Even simple GET parameters can be manipulated (e.g. `id=123; rm -rf /`). Furthermore, parameters must be validated to not start with `-` to prevent flag injection even when using array arguments. Finally, raw error messages from executed commands often include the command itself or its evaluated arguments, creating an information disclosure vulnerability.
**Prevention:** Always use `execFile`, `execFileSync`, or `spawn` with an array of arguments instead of string-based shell execution (`exec` or `execSync`). Explicitly validate that user-provided arguments intended as values do not begin with a hyphen (`-`), and rigorously validate input format (e.g. alphanumeric for IDs, numeric for counts). Always catch execution errors and return sanitized, generic error messages to the client.
