## 2024-06-05 - Fix Command Injection in docker-logs.ts
**Vulnerability:** The API route `src/pages/api/docker-logs.ts` executed a string command (`docker logs --tail ${tail} ${containerId}`) using the synchronous `execSync` function. The inputs (`tail` and `containerId`) were retrieved directly from URL search parameters without sanitization. This allowed attackers to craft malicious queries (e.g., `id=123; rm -rf /`) leading to arbitrary remote command execution (RCE) on the server.
**Learning:** Node.js's `execSync` function creates a shell to execute the command, treating string inputs as raw bash code. In addition to command injection risks, it blocks the entire event loop during execution, degrading application performance for all clients until the process completes.
**Prevention:** Avoid `execSync` and `exec` when dealing with user inputs or potentially slow external commands. Instead, use asynchronous, shell-less alternatives like `execFile` (wrapped in `promisify` to `execFileAsync`) and pass arguments as an array (`['logs', '--tail', tail, containerId]`). This guarantees inputs are treated strictly as command parameters, not executable code. Always strictly validate API inputs (e.g., checking for specific characters with `/^[a-zA-Z0-9_.-]+$/`) before passing them to OS-level utilities. Finally, properly handle streams like `stderr` which might act as valid logging outputs in containerized environments.
