## 2024-07-24 - Critical Command Injection Risk via execSync
**Vulnerability:** Node.js API endpoints (`src/pages/api/docker-logs.ts` and others) were using `execSync(command)` with user-supplied query parameters directly interpolated into the shell command string, allowing potential command injection. In addition, synchronous execution blocks the main event loop, causing denial of service on slow commands.
**Learning:** Shell strings using template literals like ``` `docker logs --tail ${tail} ${containerId}` ``` are dangerous when parsed by `execSync` because they invoke a subshell which evaluates shell metacharacters. Furthermore, synchronous I/O blocks all concurrent HTTP requests.
**Prevention:** Always refactor `execSync`/`exec` to asynchronous functions using argument arrays (e.g., `execFileAsync('docker', ['logs', '--tail', tail, id])`) to bypass shell interpolation. Combine this with strict whitelist regex validation for input parameters (e.g., `^[a-zA-Z0-9_.-]+$`) and input prefix blocking (e.g. `!id.startsWith('-')`) to prevent argument injection flags. Sanitize any outgoing error messages to prevent internal paths or secrets from leaking to clients.
