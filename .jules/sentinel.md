## 2024-06-24 - Fix Command Injection in Docker Containers API
**Vulnerability:** The API routes for Docker containers were using `exec()` (from `child_process`) to execute `curl` and `docker` commands. Unsanitized inputs concatenated directly into the shell string execution could allow for command injection, and even simple paths could be manipulated.
**Learning:** Shell strings executed via `exec` in node can inadvertently parse commands, flag injection, or shell sub-shells from inputs meant as plain arguments or ids, leading to remote code execution risks and environment variable leaks (as raw error messages were also leaked).
**Prevention:** Always use `execFile` or `execFileSync` instead of `exec` with an array of string arguments to skip shell parsing entirely. Further, validate user inputs specifically via regex to ensure they only contain safe characters (e.g., alphanumeric, `_`, `.`, `-`) and do not start with hyphens to prevent flag injection, and fail safely by returning generic error messages.
