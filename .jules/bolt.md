## 2024-07-14 - Optimize Astro DB Aggregations and Concurrent Network Requests
**Learning:** In Astro DB endpoints handling multiple resources, fetching entire tables into memory for simple counting causes an N+1 scaling bottleneck. Additionally, slow external networks calls (like to ZimaOS) shouldn't block the faster database queries when they can be run in parallel.
**Action:** Replace `db.select().from(Table)` followed by `.length` in Javascript with explicit SQL aggregations: `db.select({ value: count() }).from(Table)` combined with standard filtering (`eq`, `gte`, `inArray`). Start slow network calls at the top of the route handler as detached Promises, with `.catch(() => {})` handlers to prevent `UnhandledPromiseRejection` crashes before they are eventually `await`ed.
