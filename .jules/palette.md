## 2024-07-07 - Improved Mobile Menu Accessibility
**Learning:** Found that the full-screen backdrop overlay used to close modals or drawers (like in MobileMenu.tsx) was part of the natural tab order because it used a `<button>` element. This forces keyboard users to navigate through an invisible, non-intuitive element before reaching the actual content or explicit close controls. Additionally, interactive icon buttons lacked both explicit focus indicators and proper ARIA hiding for their internal SVG shapes.
**Action:** Always add `tabIndex={-1}` and `cursor-default` to structural, full-screen backdrop buttons used for "click-away" functionality so they are removed from the keyboard tab sequence. For interactive icon-only buttons, consistently apply `focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-[#175B37]` for visible keyboard feedback, and `aria-hidden="true"` to their inner SVG elements to prevent screen reader redundancy when the parent button already has an `aria-label`.
