## 2025-02-28 - Optimize sequential operations in dashboard-projects-health.ts
**Learning:** Checking the dev server status in a sequential `for...of` loop can be a performance bottleneck because each check waits for the previous one to complete, introducing latency, especially since it involves file system access and potentially network calls (`resolveProjectPathFromDbProject` and `getPrimaryDevServerStatus`).
**Action:** When working with loops that perform I/O operations (like file reads or external API calls) mapped from database rows, map them to an array of Promises so they execute concurrently. To preserve order (e.g., matching the database query `ORDER BY` clause), iterate through the array of promises and `await` them sequentially instead of using `Promise.all()`. Additionally, start slow network requests (like `fetchZimaOSSessionsPayload`) at the beginning of the API route handler as un-awaited Promises and attach a `.catch(() => {})` handler to safely prevent `UnhandledPromiseRejection` errors, awaiting it only when its result is actually needed.
