## 2024-05-15 - [CRITICAL] Command Injection in docker-logs API
**Vulnerability:** The `src/pages/api/docker-logs.ts` endpoint used `execSync` with unsanitized user inputs (`containerId` and `tail`) directly interpolated into the command string. This allowed for arbitrary command execution by passing shell metacharacters like `;`, `|`, or `&&` in the `id` or `tail` parameters.
**Learning:** Shell execution with user-provided parameters is highly risky. Direct interpolation is a common vector for command injection. Using an array of arguments with `execFile` prevents the shell from parsing metacharacters. Also, error messages must be sanitized to avoid leaking system or command execution details.
**Prevention:** Avoid `execSync` and `exec`. Instead, use `execFile` or `promisify(execFile)` with the arguments passed as an array. Validate all input variables rigorously (e.g., using a regex like `/^[a-zA-Z0-9_.-]+$/`) and ensure parameters don't start with a hyphen to prevent flag injection. Sanitize error messages before sending them to the client.
