## 2025-02-28 - [CRITICAL] Command Injection in GitHub Clone Endpoint
**Vulnerability:** Found a command injection vulnerability in `src/pages/api/github-clone.ts`. The endpoint accepts user-provided input (`repoName`) and directly constructs a string for a shell command (`git clone ${authUrl} ${repoName}`) which is then passed to `util.promisify(exec)`. An attacker could pass a crafted `repoName` containing bash operators (e.g., `repoName = "test; cat /etc/passwd"`) to execute arbitrary commands on the server. Furthermore, the catch block was leaking the unhandled exception message, which could contain the GitHub API token included in the `authUrl`.
**Learning:** Using `exec` directly with user input exposes the application to severe command injection risks. Additionally, error messages must be sanitized before being returned to clients to prevent exposing credentials from generated shell commands.
**Prevention:** Always use `execFile` (or its Promisified equivalent) which does not spawn a shell, thus preventing shell operator execution. Explicitly pass arguments as an array instead of string interpolation. Always use the `--` double-dash option as the first argument separating the executable and options from positional user arguments (like URLs or file paths) to prevent options injection. Furthermore, always sanitize error messages before returning them to ensure tokens or secrets are masked.
