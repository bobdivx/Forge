## 2024-06-17 - Fix Command Injection in Docker Containers API
**Vulnerability:** Command injection vulnerability in `src/pages/api/docker/containers.ts` where user-provided input (`id` and `action`) was directly interpolated into an `execAsync` curl command (`curl -s -X ${method} --unix-socket /var/run/docker.sock "${url}"`). The `exec` command executes inside a shell, allowing an attacker to break out of the string quotes and inject arbitrary shell commands.
**Learning:** Shell utilities like `exec` or `execAsync` (when `promisify(exec)`) evaluate the entire command string in a shell. Even if interpolated values are quoted, characters like `$()`, `\``, `;`, `&&`, or `||` can lead to arbitrary code execution.
**Prevention:** Always use `execFile` or `execFileAsync` which executes the executable directly without invoking a shell, inherently preventing shell injection. Additionally, always validate inputs (e.g. against `/^[a-zA-Z0-9_.-]+$/`) to prevent argument injection where user input could be misinterpreted as a command flag (e.g. starting with `-`).
